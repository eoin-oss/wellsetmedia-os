# Copy Quality Bar

> Run before any copy deliverable is delivered. This is the craft standard and it is
> not a preference — every member gets it. Hygiene (em dashes, AI phrases, cadence,
> foil framing, the three-test, specificity scoring) lives in
> `Context/Marketing/copy-rules.md` and is NOT repeated here. This file covers what
> that one does not: whether the copy was actually built correctly.

## 1. Framework application — the craft floor

| Rule | Pass criteria |
|---|---|
| Pre-writing analysis present | Awareness level, market sophistication, LF8 desire, and the reader's existing conversation are stated BEFORE the copy |
| Awareness level correct | Strategy matches the identified level (Level 2 copy does not open on price) |
| Sophistication match | The angle matches the market's stage |
| LF8 alignment | The primary desire drives the lead; secondary desires layer through |
| Collier principle | The opening enters the conversation already happening in the reader's head |
| **Headline variants** | **Minimum 3 headline/hook options per deliverable. One is not a deliverable.** |
| **Proof near CTAs** | **Every CTA has supporting proof within 2 paragraphs above it** |
| **Objections before close** | **Top 2-3 objections addressed before the final CTA** |

The three bolded rules are the ones whose absence reads as "technically fine but flat."

## 2. Deliverable completeness

| Deliverable | Minimum |
|---|---|
| VSL | Hook · Credibility · Story · Problem · Solution · Offer · Guarantee · CTA (7+ sections) |
| Email | Subject + preview text + body + CTA for every email; sequence logic stated |
| Ad | Format specified, 3+ hook variants, within platform character limits |
| Sales page | 10+ sections, proof near every CTA, stacked CTAs, mobile-scannable |
| Confirmation page | Trust builder + agenda + social proof + what to prepare + CTA |
| Webinar | Hook + teaching sections + transition + offer + FAQ + close |

No blanks. No `[TODO]` markers. Sections are not skipped, renamed, or merged without stating why.

## 3. Specificity

| Rule | Pass criteria |
|---|---|
| No vague claims | No "many", "several", "often", "recently" without a number |
| Named entities | The actual business and offer names, not "our product" / "the program" |
| Proof specificity | Testimonials carry full names, companies, numbers, timeframes |
| CTA specificity | Every CTA says what happens next — "Book your call", not "Get started" |
| Benefits over features | Every feature carries a "which means" bridge to a specific outcome |
| Urgency is real | Scarcity reflects an actual constraint. Never manufactured. |

## 4. Copy-specific banned phrases

These are IN ADDITION to the AI-phrase list in `copy-rules.md`. Each is an unsourced
claim wearing the costume of authority:

- "In today's competitive landscape" — name the landscape and what makes it competitive
- "Consumers are increasingly" — cite the data or cut it
- "Industry experts agree" — which experts? Name them
- "Studies show" — which studies? Cite them
- "The market is expected to" — cite the projection
- "Best practices suggest" — whose practices?
- "According to various sources" — name them individually
- "It goes without saying" / "Needless to say" — then don't say it
- "As we all know" — they may not. State it and cite it
- "Take your [X] to the next level" — define the level
- "Are you ready to" — weak CTA opener; state what they get
- "Paradigm shift", "Holistic" — see `copy-rules.md` for the full AI-phrase list

## 5. Funnel consistency

> Applies from the second deliverable onward for a workspace with a `funnel-brief.md`.

| Rule | Pass criteria |
|---|---|
| Mechanism name | The core mechanism appears by name in every major deliverable |
| Anchor stat | Identical number and framing everywhere it appears |
| CTA micro-copy | Button and link text matches the brief exactly. No synonyms. |
| Transformation promise | Before / after / timeframe consistent across VSL, page, ads, emails |
| Enemy frame | The same enemy named or implied throughout |
| Objection reframe | Each objection uses the same reframe wherever it appears |

## 6. Hard stops

Stop all work and wait for a human when:

| Condition | Action |
|---|---|
| `knowledge.md` missing offer, voice profile, or audience | Stop. List the missing fields. |
| Zero proof available | Stop. "Copy without proof will underperform. How do you want to handle it?" |
| Voice profile contradicts the request | Present the conflict. Ask which wins. |
| Instructions violate a core principle ("remove all proof") | State the risk in one sentence. Ask for confirmation. |
| A banned phrase or em dash reached the output | Fix before delivering. Re-run the check. |

## 7. Soft warnings — note and continue

Thin proof · sparse voice profile · a missing reference file · a section shorter than
ideal. Write with what exists, name the gap and its consequence, keep going.

## 8. Scoring

| Score | Meaning |
|---|---|
| 5.0 | Exceptional. Deployable as-is. Voice match indistinguishable. |
| 4.0–4.9 | Strong. Meets standard. Minor polish. |
| 3.0–3.9 | Acceptable but lacks punch, specificity, or voice accuracy. |
| 2.0–2.9 | Below standard. Missing sections, weak proof, generic language. |
| 1.0–1.9 | Failing. Banned phrases, fabricated proof, unusable. |
| 0.0–0.9 | Reject. |

**Pass threshold: 4.0.** Below that, the deliverable is not delivered — it is revised.

## 9. Self-check — append to every deliverable

```
## Copy Quality Self-Check
- Em dashes: [0] (target 0)
- Banned phrases: [0] (target 0)
- 3+ consecutive short sentences: [0] (target 0)
- Headline/hook variants: [X] (target 3+)
- Proof near CTAs: [X/X covered]
- Objections addressed: [X] (target 3)
- Pre-writing analysis completed: [yes/no]
- Voice match confidence: [high/medium/low]
```

Showing the score is part of the deliverable. It is how the member sees the bar being held.
